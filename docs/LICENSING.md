## 免费许可允许什么

PolyForm Noncommercial 允许其条款范围内的使用、修改与分发，包括非商业目的、列明的个人用途，以及条款列明的公益、教育、公共研究、公共安全或健康、环保、政府机构用途。上述机构有独立的许可条款，不能简单解释为「涉及收费或资助就必须付费」。

企业内部业务使用、产品集成、收费部署、SaaS、付费分发等，若超出标准许可已经授予的范围，需要单独商业授权。是否收费不是唯一判断标准；如果使用完全基于历史 MIT 权利，则依该 MIT 许可处理，无须仅因本次迁移购买授权。

不得把新覆盖作品声明为「MIT 或 PolyForm 二选一」，也不得把本模式宣传为 OSI 意义的开源。项目不提供学校系统、账号、个人数据或第三方商标的使用授权。

## 商业授权流程

1. 在 [项目 Issues](https://github.com/YukikazeKaede/xinxinxiangying/issues/new) 以「商业授权咨询」为题联系维护者。公开内容只写用途概述、软件版本和申请主体类型；不要公开电话、证件、合同、客户资料或其他保密信息。维护者再提供私下沟通方式。
2. 双方核对涉及代码与权属、使用主体、产品、部署或服务、修改与再分发需求、期限、规模及第三方许可。历史 MIT 代码与新受覆盖作品分别列明。
3. 有权授权的一方提供正式合同与授权清单，约定费用、付款、生效条件、支持及责任；再分发、转授权、关联公司使用及后续版本权利，均须明确写入。
4. 双方完成约定的签署与生效条件后，将授权编号、签署版本和范围在私下留档。询价、提交 Issue、报价或捐赠均不自动产生商业许可。本说明不是商业授权合同。

不预设价格、独占权、永久更新、技术支持或商用承诺。维护者应在签约前核对其可授予的权利；不能用一份商业合同豁免无权豁免的第三方义务。

## 商业授权清单（签约时填写）

| 字段 | 合同需明确的内容 |
| --- | --- |
| 当事方 | 双方真实法律主体、签署权限与通知方式 |
| 软件范围 | 仓库、版本、提交、模块及许可资产清单；历史 MIT 和第三方排除项 |
| 使用范围 | 主体、产品、部署、用户或实例数量、地区、期限 |
| 授权权利 | 使用、修改、内部复制、对外托管、二进制或源码分发、转授权分别约定 |
| 商业条件 | 费用、币种、税费、支付、生效、续期、终止及终止后处理 |
| 其他条款 | 署名、知识产权、保密、支持、保证与责任、适用法律及争议解决 |
